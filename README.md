# アイデアを、頭の中だけで終わらせない

> おい、頭の中にあるもん、ちょっと出してみろ。意外と、みんな見るぞ。

個人が頭の中に持っているアイデアを、文章・画像・スケッチ・資料などから気軽に外へ出し、AIで可視化し、需要・価格・実現コストを検証し、協力者や事業化の可能性につなげるプラットフォーム。

## プロダクトの考え方

- **入口は軽く。** 完成した企画書も、起業の決意も必要ない。
- **可視化で伝わる形に。** テキストだけでも、添付資料があっても、MVPレベルのイメージに変換する。
- **反応をデータに。** 欲しい人、払える価格、実現できる人、必要な費用を可視化する。
- **実現は本人が選ぶ。** 投稿だけで終わってもよく、希望すれば協業や資金調達へ進める。
- **アイデアと利用者を守る。** 公開範囲、知的財産、詐欺対策、個人情報、法令順守を設計の前提にする。
- **小さく始める。** 最初はアイデア入力・構造化・簡易可視化・需要調査に絞る。

## MVPの段階的なスコープ

**最初に検証する範囲（P0）**
1. 一文からのテキスト入力
2. 課題・想定する人・解決案・分かっていること・未確認事項の構造化
3. 出力の編集・やり直し・破棄
4. 公開や登録を強制せず、未実装の導線はデモと明示

**価値を確認してから追加する候補（P1以降）**
- 下書き保存・削除
- 画像・資料の任意添付
- テンプレート型の概念図・画面モックアップ
- 入力値と仮定を明記した簡易コスト試算
- 匿名の反応収集、通報・削除依頼
- 限定共有・公開機能（認可・同意・撤回のテスト完了後）

公開、保存、添付、需要調査、マッチングは、仕様書に記載しただけでは実装済みにならない。段階ごとの受入基準と安全性チェックを満たしてから追加する。

詳細は [docs/CONCEPT.md](docs/CONCEPT.md) を参照。

## 開発原則

- 生成された推測と、投稿者が確定した情報を区別する。
- 「購入したい」という回答と実際の購入・契約を区別する。
- 画像・モックアップと、実際に動作するMVPを混同しない。
- 有料機能は実際の処理コストを計測してから価格を決める。
- 出資・融資・資金の預かりや送金は、法的要件と運営体制を確認するまで実装しない。
- 最初から全機能を作らず、最小構成で需要を検証する。

## 開発状況

**開発初期段階です。** コンセプト・MVP仕様・LPのたたき台を整備中です。

- LP：[`index.html`](index.html)（コンセプト紹介用。画面モックは説明用です）
- ローカル試作：[`prototype/index.html`](prototype/index.html)（外部通信・AI・保存・公開なし。一文入力、テンプレート整理、編集、コピーを試せます）
- 設計資料：[`docs/`](docs/)
- 未実装：AI生成、サーバー保存、アカウント認証、需要分析、公開投稿、マッチング、課金、本人確認連携
- 未確認：スマートフォン実機での表示、公開デプロイ、公開URLでの動作

ローカル試作ではテンプレート型の整理操作のみ試せます。入力内容は送信・保存されません。AI生成・サーバー保存・公開投稿・課金・マッチング機能は利用できません。公開前に動作確認と必要な法務・プライバシー確認を行います。
