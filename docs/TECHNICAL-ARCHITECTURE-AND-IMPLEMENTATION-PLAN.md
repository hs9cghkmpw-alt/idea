# PON 技術構成・実装バックログ（ゼロ円優先）

更新日：2026-10-14  
状態：構成案。サービス選定・本番実装・セキュリティ検証は未完了。

## 1. 今回の判断

**まずブラウザ内だけで動く試作を作り、価値を確かめてからサーバーを導入する。**

追加した `prototype/index.html` は、外部通信・AI API・アカウント・サーバー保存を使わないローカル試作。短いアイデアを入力し、項目ごとに編集し、整理メモをコピーする操作を検証する。入力内容はページを閉じると失われる。AIが生成したように見せない。

これにより、初期段階でのAPI費用、アカウント情報漏えい、認可バグ、ユーザー投稿データの保管リスクを避けながら、初回体験の検証を始められる。

## 2. 推奨アーキテクチャの段階

### Stage 0：静的LP＋ローカル試作（現在）

- `index.html`：コンセプトLP
- `prototype/index.html`：ブラウザ内だけで動く入力・整理メモ試作
- HTML/CSS/JavaScriptのみ。外部ライブラリ・外部API・サーバー保存なし
- 入力はページのメモリ上だけに保持し、ページを閉じると消える
- 目的：利用者が価値を理解するか、整理結果が役立つか、項目を編集したいかを確認

**制約：** この段階ではAI分析、永続保存、アカウント、複数端末同期、共有、公開、マッチングはない。ブラウザのコピー機能はユーザーが明示操作した場合のみ使う。

### Stage 1：ローカルの体験改善

- 実利用者のフィードバックを受けて文言、入力例、項目を改善
- 入力内容を外部へ送信しないことをコードレビューで確認
- キーボード操作、画面読み上げ、コントラスト、モバイル表示を確認
- 計測を行う場合も、本文や個人情報は収集せず、必要性と同意を先に検討

### Stage 2：サーバー側AI API（必要性を検証した後）

- フロントエンドはAPIキーを持たない
- APIサーバーに認証・入力長制限・レート制限・タイムアウト・再試行上限を実装
- 月間予算の上限と、有料APIを停止する運営用スイッチを設ける
- 上限到達・障害時はローカルのテンプレート体験に戻す
- 送信前に、外部事業者へ送られる情報、保持条件、学習利用、利用規約を説明
- サーバーログへアイデア本文、認証トークン、個人情報を記録しない

### Stage 3：アカウント・非公開保存

- 認証プロバイダーとDBは、費用・無料枠・データ処理条件を比較してから決める
- 認証と認可を分離。すべての読み書きでサーバー側所有者チェック
- 非公開を既定値にする。保存しただけで公開されない
- 削除、保持期間、バックアップ消去の運用を決める
- 他アカウントからの読み取り・更新・削除を試験し、失敗したら公開を止める

### Stage 4：共有・公開・協業

- 公開する情報と相手を利用者が確認し、明示的に同意した場合のみ共有
- 公開同意の版・日時・範囲を記録し、撤回・削除・ブロックを実装
- 通報・問い合わせ・違反対応の運用を準備
- 本人確認は協業へ進む段階で導入を検討。PONは書類画像・マイナンバーを保存しない
- 法務・プライバシー・安全性の確認が済むまでは、一般公開やマッチングを有効化しない

## 3. 無料・低コストサービス選定ルール

現時点では特定ベンダーを決定しない。無料枠は変更されるため、実装開始時に公式料金・利用制限・データ処理条件を確認する。

比較項目：
1. 無料枠の制限、超過時に自動課金されるか
2. クレジットカード登録の要否
3. データの保管場所、保持期間、削除方法
4. 外部AI利用時の学習利用・オプトアウト条件
5. 認証・DBのアクセス制御と監査機能
6. データのエクスポートとサービス移行のしやすさ
7. 休眠・無料枠超過時の挙動
8. 管理者が利用停止できるか

「無料プランがある」だけでゼロ円運用とみなさない。自動課金を避ける設定、予算通知、利用停止手段を確認する。

## 5. プロトタイプの手動受入テスト

1. ページを開き、AI・保存・公開機能が未接続であると分かる。
2. 入力を空にして「整理する」を押すと、エラーが表示され、結果画面は開かない。
3. 例文ボタンで入力欄が埋まる。
4. 一文を入力して整理すると、入力内容が要約・既知情報へ表示される。
5. 課題・対象者・解決案の各項目を手動で編集できる。
6. 編集内容をコピーできるか確認する。
7. 「最初からやり直す」で結果と入力が消える。
8. 開発者ツールのNetworkを開いて操作し、入力に伴う外部リクエストが発生しない。
9. ページを再読み込みすると、前の入力が保存されていない。
10. 狭い画面幅で横スクロールや要素の重なりが発生しない。

## 6. 完了の定義

コードをリポジトリへ追加しただけでは完了扱いにしない。少なくとも以下を分けて記録する。

- **コード作成：** ファイルが保存されている
- **静的レビュー：** ソースを読んで要件を確認した
- **実行確認：** 対象ブラウザで実際に動かした
- **利用者確認：** 目的の利用者が触って価値を評価した
- **公開確認：** デプロイ先で安全性・表示・運用を確認した

この文書のチェックが未完了の項目は、完了と表現しない。
