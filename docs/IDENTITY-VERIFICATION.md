# PON 本人確認・信用設計（MVP方針）

## 1. 決定方針

- アイデアの投稿・基本閲覧は、本人確認前でも可能とする。投稿者はニックネームで活動できる。
- マッチング申請の送信・承認後の協議など、他の利用者と実質的な協業に進む段階では、本人確認を必須とする。
- PONはマイナンバー（12桁の個人番号）を取得・保存しない。
- 本人確認書類の画像や、本人確認に不要な氏名・住所等をPON側で保存しない設計を目指す。
- 外部の本人確認サービスを利用し、PONは確認結果など必要最小限の情報を受け取る。
- 「本人確認済み」は、実在する本人であることの確認を示すものであり、誠実さ・能力・取引の安全性を保証する表示ではない。

## 2. 認証フロー

1. 利用者は匿名・未確認の状態でアイデア投稿などの基本機能を利用できる。
2. マッチング・協議機能を利用しようとした際に、本人確認を案内する。
3. 外部サービス上で本人確認を実施する。
4. PONのサーバー側で、外部サービスから返された確認結果の真正性を検証する。
5. PONは機能制御に必要な最小限の状態を保存する。
6. 他の利用者には「本人確認済み」等の状態だけを表示し、氏名・住所・本人確認書類を自動公開しない。

## 3. PON側で保存する情報

原則として、必要性を確認したうえで次の最小限に限定する。

- 本人確認状態（未確認／確認中／確認済み／要再確認など）
- 確認方式
- 確認日時
- 外部サービスの照合用ID（必要な場合のみ。用途・保存期間を定義する）

PONではマイナンバー、本人確認書類の画像、認証に不要な氏名・住所等を保存しない。外部サービスから受け取るデータ項目は契約前に確認し、不要な項目は受信・保存しない設計とする。

## 4. 外部サービス選定

以下を比較してから採用を決定する。

- JPKI（公的個人認証）対応の有無
- マイナンバーカード以外の本人確認手段
- 初期費用、月額費用、従量課金、無料枠
- 本人確認結果のサーバー側検証方法
- 個人情報の保存場所、暗号化、アクセス管理、保存期間、削除方法
- 再委託先、事故発生時の通知・対応
- 利用規約、個人情報保護法上の役割分担、監査・問い合わせ対応
- 海外利用者への対応（必要になった段階で検討）

費用と法令対応を確認するまで、特定のサービスや有料契約を確定しない。独自に本人確認書類を収集・保管する方式は初期案にしない。

## 5. 企業アカウント

個人の本人確認と、企業の実在確認・担当者の権限確認は別の確認事項として扱う。企業名を表示する場合は、未確認と確認済みを区別する。企業の確認済み表示も、企業の誠実さや取引履行を保証するものではない。

## 6. 本人確認だけでは防げないリスク

本人確認後も、詐欺、虚偽説明、アカウント乗っ取り、契約不履行、アイデアの無断利用等は起こり得る。通報・ブロック、違反アカウントの制限、協議履歴、公開範囲制御、情報開示の同意記録などを組み合わせる。

## 7. 受け入れ条件

- 未確認ユーザーはアイデア投稿など、許可された基本機能を利用できる。
- 未確認ユーザーはマッチング・協議機能を利用できない。
- 外部認証結果はサーバー側で検証し、クライアント表示だけを信用しない。
- PONのデータベース・ログにマイナンバーや本人確認書類画像を保存しない。
- 本人確認済みでも、個人の氏名・住所・連絡先は自動公開されない。
- 本人確認の状態と、行動実績・能力実績を別々に表示する。
- 本人確認サービスの停止・障害時の扱いを定義する。
- 利用者向け説明に、本人確認が詐欺や取引トラブルを完全に防止するものではないと明記する。

## 8. 未決事項

- 外部サービスの選定と実際の料金
- どの協議操作を本人確認必須の境界とするかの最終確定
- 再確認が必要になる条件
- 確認記録の保存期間と削除基準
- 法務・プライバシー面の最終確認

この文書はMVPの設計方針であり、特定の認証サービスとの契約や法的適合性の確定を意味しない。
